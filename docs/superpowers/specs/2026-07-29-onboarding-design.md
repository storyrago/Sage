# 소셜 로그인 후 프로필 온보딩 설계

- 작성일: 2026-07-29
- 범위: 신규 소셜 회원이 첫 로그인 직후 닉네임을 직접 정하는 온보딩 화면 + 닉네임 수정 API
- 관련 이슈: storyrago/Sage#68

## 1. 배경과 목표

로그인은 소셜 전용(구글·카카오)이다. 그런데 **닉네임을 사용자가 정할 기회가 없다.** provider가 준 값을 그대로 쓴다.

| provider | 닉네임 출처 | 결과 |
|---|---|---|
| 구글 | `name` 클레임 → 앞 10자 절단 | 실명이 채팅에 그대로 노출된다 (`Alexander Longname` → `Alexander`) |
| 카카오 | `nickname` 클레임 | 없으면 **`user`** — 여러 회원이 같은 이름이 될 수 있다 |

게다가 **닉네임 수정 API가 없다.** `MemberController`에는 프로필 이미지 변경(`PATCH /api/members/me/profile-image`)만 있어서, 한번 정해지면 사용자가 바꿀 수 없다. 설정 화면에 프로필 편집 UI가 있지만 백엔드에 반영되지 않는다.

목표는 두 가지다.

1. 신규 회원이 **첫 로그인 직후 닉네임을 직접 정하게** 한다
2. **닉네임 수정 경로를 만든다** — 온보딩과 설정 화면이 같은 API를 쓴다

두 번째는 온보딩의 부수 효과가 아니라 전제다. 온보딩을 건너뛸 수 있게 만들었으므로(§2 D1), 나중에 바꿀 수단이 반드시 있어야 한다.

## 2. 결정 사항

**D1. 온보딩은 건너뛸 수 있다.**
"나중에 하기"를 제공하고, 백엔드는 온보딩 미완료 회원의 API를 막지 않는다. 필수 관문으로 만들면 인가 상태를 검사하는 필터가 한 겹 늘고 첫 진입 마찰이 커진다. 대신 건너뛴 사용자가 나중에 바꿀 수 있도록 설정 화면의 닉네임 편집을 함께 연결한다.

**D2. 온보딩에서 받는 것은 닉네임뿐이다.**
프로필 사진은 provider가 준 값을 그대로 쓰고, 변경은 설정 화면에서 한다(이미 동작하는 기능이다). 상태 메시지는 현재 `localStorage`에만 저장되는데, 그 백엔드화는 별도 과제로 남긴다(§8). 첫 관문은 입력 하나가 적절하다.

**D3. `nickname`을 `VARCHAR(20)`으로 늘린다.**
현재 10자는 사용자가 직접 정하는 값으로는 좁다. 카카오 닉네임 정책도 20자다. `OAuthService.toNickname`의 절단 길이도 함께 20으로 맞춘다.

**D4. 마이그레이션 시점의 기존 회원은 온보딩 대상이 아니다.**
V6에서 기존 행을 온보딩 완료로 표시한다. 이미 서비스를 쓰던 사람에게 갑자기 설정 화면이 뜨는 것을 피한다. 그들의 닉네임은 자동 생성값으로 남지만, 설정 화면에서 바꿀 수 있다(D1).

## 3. 스키마 (Flyway V6)

```sql
ALTER TABLE members ADD COLUMN onboarded_at DATETIME(6) NULL;
ALTER TABLE members MODIFY nickname VARCHAR(20);

-- 마이그레이션 시점의 기존 회원은 온보딩 대상이 아니다
UPDATE members SET onboarded_at = NOW(6);
```

`onboarded_at`이 `NULL`이면 온보딩을 아직 지나지 않은 회원이다. 완료든 건너뛰기든 타임스탬프를 찍어 다시 뜨지 않게 한다. 배포 이후 생성된 회원만 `NULL`로 시작한다.

`nickname` 확장은 기존 데이터에 무해하다(축소가 아니라 확장).

## 4. API

책임을 하나씩 갖는 엔드포인트 두 개를 만든다.

| 엔드포인트 | 역할 | 사용처 |
|---|---|---|
| `PATCH /api/members/me` | 닉네임 수정 | 온보딩, 설정 화면 |
| `POST /api/members/me/onboarding` | `onboarded_at` 기록 | 온보딩 (완료·건너뛰기 공통) |

- 완료 = `PATCH` → `POST`
- 건너뛰기 = `POST`만

`시작하기`를 눌렀을 때 닉네임이 미리 채워진 값과 동일하더라도 `PATCH`를 호출한다. "사용자가 이 이름을 선택했다"는 사실이 서버에 남는 편이 단순하고, 분기가 줄어든다.

**둘로 나눈 이유**: 닉네임 저장이 실패하면 온보딩 완료로 기록되지 않아 사용자가 다시 시도할 수 있다. 한 엔드포인트로 합치면 부분 실패 시 상태가 어긋난다. 또한 `PATCH`는 설정 화면에서 그대로 재사용된다.

**`PATCH /api/members/me`**
- 요청 본문: `{ "nickname": "..." }`
- 검증: `@NotBlank`, `@Size(max = 20)`. 앞뒤 공백은 제거한 뒤 검증한다.
- 응답: `MemberResponse`
- 자기 자신만 수정한다(`@AuthenticationPrincipal`의 memberId 사용). 경로에 대상 id를 받지 않는다.

**`POST /api/members/me/onboarding`**
- 본문 없음
- `onboarded_at`이 이미 있으면 아무것도 하지 않는다(멱등)
- 응답: `MemberResponse`

## 5. 응답 DTO

`MemberResponse`에 `onboarded: boolean`을 추가한다. `onboardedAt != null`을 불리언으로 노출한다 — 프론트는 판별만 하면 되고 타임스탬프가 필요 없다.

## 6. 프론트

**진입 판별**
`App.tsx`는 OAuth 해시 핸드오프와 세션 복원 양쪽에서 `getMe`를 호출한다. 그 결과의 `onboarded`가 `false`면 채팅 대신 온보딩 화면을 렌더한다.

```
로그인/세션 복원 → getMe
   ├ onboarded === false → 온보딩 화면
   └ onboarded === true  → 기존 채팅 화면
```

**온보딩 화면**(신규 컴포넌트)
- 기존 로그인 카드의 디자인 토큰을 따른다: 카드 `#1C241F` / `1px solid #2D362F` / radius 22, 입력 `#252E28` / radius 12, 기본 버튼 `#7AAE92` 배경 + `#12241B` 글자 / radius 13
- 구성: 프로필 이미지(없으면 기본 아이콘) → 제목 → 설명 → 닉네임 입력 → `시작하기` → `나중에 하기`
- **닉네임 입력에 provider가 준 현재 닉네임을 미리 채운다.** 빈 칸보다 마찰이 적고, 그대로 진행하거나 지우고 새로 쓸 수 있다
- `20자` 제한을 입력 위에 `n / 20` 카운터로 노출한다. 제출 후 거부보다 입력 중 안내가 낫다
- `나중에 하기`는 시각적으로 약하게 둔다(무채색 텍스트, 테두리 없음) — 건너뛰기는 열어두되 기본 동선은 닉네임 설정이다
- 빈 닉네임으로 `시작하기`를 누르면 클라이언트에서 막고 안내한다

**설정 모달**
닉네임 편집을 `PATCH /api/members/me`에 연결한다. 현재 이 입력은 로컬 상태만 바꾸고 새로고침하면 원복된다.

## 7. 검증

- **유닛 테스트**
  - 닉네임 수정 성공 → 저장된 값 확인
  - 빈 문자열·공백만 있는 닉네임 거부
  - 20자 초과 거부, 20자 정확히는 허용
  - 온보딩 기록 멱등 — 두 번 호출해도 `onboarded_at`이 최초 값 그대로
- **마이그레이션**: 기존 행이 있는 DB에 V6 적용 → 모든 기존 회원의 `onboarded_at`이 채워지고, `nickname` 컬럼이 `VARCHAR(20)`인지 확인
- **E2E(로컬)**
  - 신규 소셜 로그인 → 온보딩 화면 노출 → 닉네임 저장 → 채팅 진입
  - 로그아웃 후 재로그인 → 온보딩이 다시 뜨지 않음
  - 건너뛰기 → 채팅 진입, 재로그인 시에도 안 뜸
  - 설정 화면에서 닉네임 변경 → 새로고침 후에도 유지, 채팅 메시지 작성자 이름에 반영
- 백엔드 `./gradlew test`, 프론트 `npm run lint && npm run build`

## 8. 배포 영향

- **스키마 변경 있음** — Flyway V6, 배포 시 자동 적용
- 환경변수 변경 없음
- 배포 직후 기존 회원은 온보딩을 보지 않는다(D4). 배포 이후 가입자만 대상이다
- 전진 전용이다. V6 적용 후 이전 이미지로 롤백하면 `ddl-auto: validate`가 새 컬럼에서 실패한다

## 9. 범위 밖

- 온보딩에서 프로필 이미지 변경 — 설정 화면에 이미 있다
- 상태 메시지 백엔드 저장 — 현재 `localStorage`에만 있는 가짜 저장이다. 알림 토글 3종과 함께 별도 과제로 다룬다
- 온보딩 미완료 회원에 대한 서버 측 접근 제한 — D1에서 제외했다
- 닉네임 중복 검사 — 현재 닉네임은 표시용이고 유일성 제약이 없다. 유지한다
