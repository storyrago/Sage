# 답장(Reply) 기능 Implementation Plan

> **실행 방식:** hands-on 학습 프로젝트 — 재민 님이 직접 구현하거나 Claude가 구현 후 리뷰. 참고 코드는 "이 방향". 체크박스(`- [ ]`)로 추적.

**Goal:** 특정 메시지에 답장 — 메시지에 부모 참조를 달고 버블에 부모 인용을 표시(STOMP·REST 두 경로, 프론트 UI 복원).

**Architecture:** `Message` 자기참조(`reply_to_id`) 추가. `MessageRequest.replyToId` → `MessageService.create`가 부모 조회해 연결 → `MessageResponse.replyToId`로 방송. 프론트는 #44에서 지운 답장 UI를 복원하고 `replyToId`를 send 경로에 실어보냄.

**Tech Stack:** Spring Boot(JPA 자기참조, STOMP/REST), JUnit(빌드 검증), React + TypeScript, MySQL(로컬 update / 운영 validate + 수동 ALTER), Node E2E.

## Global Constraints

- **⚠️ 스키마 변경 있음** — `messages.reply_to_id` 컬럼 추가. 운영 `ddl-auto: validate`라 **RDS 수동 ALTER 먼저 → 배포**(아래 "배포 준비" 참조). 로컬 `application-local`은 `update`라 자동 생성.
- `MessageResponse`엔 **`replyToId`만**(부모 스냅샷 X). 프론트는 전체 로드된 메시지에서 `find`로 부모를 찾음.
- 부모 없으면 **null 취급**(관대). 이모지 반응·삭제는 복원하지 않음(답장만).
- 메시지 생성 경로 **2곳**(STOMP `ChatMessageController` + REST `MessageController`) 모두 `replyToId` 전달.

    public Message create(String content, String imageUrl, Long memberId, Long chatroomId, Long replyToId){
        Member member = memberService.getMemberById(memberId);
        ChatRoom chatRoom = chatRoomService.getChatRoomById(chatroomId);

                ? messageRepository.findById(replyToId).orElse(null)
                : null;

        Message message = new Message(content, imageUrl, member, chatRoom, replyTo);
        return messageRepository.save(message);
    }

  const handleSendMessage = async (text: string, replyToId?: string) => {
    if (!token || !selectedChannelId) return;

    const sentOverStomp = stompRef.current?.send(selectedChannelId, text, replyToId) ?? false;
    if (!sentOverStomp) {
      const saved = await sendMessage(token, selectedChannelId, text, replyToId);

    }
