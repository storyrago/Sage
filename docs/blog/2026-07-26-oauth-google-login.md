# OAuth는 어떻게 동작할까? — 채팅 프로젝트에 구글 로그인 붙이기

이메일/비밀번호 로그인은 이미 만들어 뒀다. 그런데 "Google로 로그인" 버튼 하나면 회원가입도 로그인도 끝나는 게 요즘 앱의 기본이다. 그래서 이 채팅 프로젝트에도 Google 소셜 로그인을 붙여보기로 했다. 이번 글은 OAuth가 뭐고, 그걸로 구글 로그인을 어떻게 붙였는지에 대한 기록이다.

## OAuth를 왜 쓸까

처음엔 이렇게 생각했다.

> "그냥 구글 이메일이랑 비밀번호를 받아서 우리가 확인하면 되는 거 아냐?"

절대 안 된다. 남의 서비스(구글) 비밀번호를 우리 서버가 받는 순간 그건 사고다. OAuth의 핵심 아이디어는 **비밀번호를 우리가 직접 받지 않는다**는 것이다.

대신 이렇게 흘러간다.

- 사용자를 **구글로 보낸다.**
- 인증(비밀번호 입력·동의)은 **구글이 대신 해준다.**
- 구글은 "이 사람 맞다"는 증표만 우리 서버에 돌려준다.

우리는 비밀번호를 한 번도 보지 않는다. 인증이라는 위험한 일을 구글에 위임하는 것이다.

## 로그인은 이렇게 흘러간다

```
[브라우저] --클릭--> [우리 서버] --리다이렉트--> [구글 로그인/동의]
                                                      |
[채팅 화면] <--JWT-- [우리 서버] <--인가 코드-- [구글이 콜백]
```

1. 사용자가 "Google로 로그인" 클릭 → 우리 서버가 구글 인증 페이지로 리다이렉트.
2. 사용자가 구글에서 로그인하고 동의.
3. 구글이 우리 서버의 **콜백 주소**로 인가 코드를 들고 돌려보낸다.
4. 우리 서버가 그 코드로 구글에게서 사용자 정보(이메일·이름 등)를 받아온다.
5. 그 사용자를 우리 DB에서 찾거나 새로 만들고, **우리 서비스의 JWT**를 발급한다.
6. JWT를 프론트로 넘겨 로그인 완료.

## 설정: 구글에서 OAuth 클라이언트 만들기

코드를 붙이기 전에, 구글에 "우리 앱"을 등록하고 열쇠(client id/secret)를 받아야 한다. [Google Cloud Console](https://console.cloud.google.com)에서 진행한다.

**1. 프로젝트를 만들고 OAuth 동의 화면을 구성한다.** 대상은 **외부(External)** 로 둔다. 구글 계정이 있는 사람이면 로그인할 수 있게 하는 설정이다.

![동의 화면 대상 외부 선택](이미지_URL)

**2. 사용자 인증 정보 → 클라이언트 만들기 → 유형은 "웹 애플리케이션".**

<!-- 📎 이미지: OAuth 클라이언트 ID 만들기 - 애플리케이션 유형 '웹 애플리케이션' — 업로드 후 교체 -->
![클라이언트 유형 웹 애플리케이션](이미지_URL)

**3. 승인된 리디렉션 URI를 넣는다.** 여기가 제일 중요하다. 구글이 인증을 마치고 사용자를 **돌려보낼 주소**인데, 한 글자라도 틀리면 `redirect_uri_mismatch`로 막힌다. 경로 `/login/oauth2/code/google`는 Spring Security 기본값이고, 로컬용과 배포용 두 개를 함께 넣는다.

```
http://localhost:8080/login/oauth2/code/google
https://<내-배포-도메인>/login/oauth2/code/google
```

![승인된 리디렉션 URI 입력](이미지_URL)

**4. 만들기를 누르면 클라이언트 ID와 시크릿이 나온다.** 이 두 값을 복사해 둔다. 시크릿은 노출되면 안 되니 코드에 직접 박지 않는다.

<!-- 📎 이미지: 발급된 클라이언트 ID / 시크릿 팝업 — 업로드 후 교체 -->
![클라이언트 ID와 시크릿 발급](이미지_URL)

**5. 받은 값을 설정에 넣는다.** 코드에 직접 쓰지 않고 환경변수로 주입한다.

```yaml
spring:
  security:
    oauth2:
      client:
        registration:
          google:
            client-id: ${GOOGLE_CLIENT_ID}
            client-secret: ${GOOGLE_CLIENT_SECRET}
            scope: [openid, email, profile]
```

`scope`의 `openid`·`email`·`profile`은 "구글에게 이 사용자의 어떤 정보를 달라고 할지"다. 우리는 신원 확인(`openid`)과 이메일·기본 프로필이면 충분하다.

## Spring Security로 붙이기

Spring Security는 이 흐름을 거의 다 대신해준다. `oauth2Login`만 켜면 리다이렉트·콜백·코드 교환을 알아서 처리한다.

```java
.oauth2Login(o -> o
    .userInfoEndpoint(u -> u.oidcUserService(customOidcUserService))
    .successHandler(oAuth2SuccessHandler)
    .failureHandler(oAuth2FailureHandler))
```

내가 채워야 하는 건 세 가지였다.

- **소셜 제공자 + 키** — 위에서 만든 클라이언트의 `client-id`/`client-secret` (설정에 이미 넣었다).
- **로그인 성공 시 할 일** — 구글에서 받은 사용자를 DB에서 찾거나 만들고, 우리 JWT를 발급한다(`SuccessHandler`).
- **사용자 매칭 규칙** — 이메일이 아니라 구글의 고유 ID(`sub`)를 신원으로 삼았다. 이메일은 바뀔 수 있어도 `sub`는 그 사람 그대로이기 때문이다.

## 로그인 후: 토큰을 프론트로 넘기기

백엔드가 JWT를 발급했으면, 이걸 프론트(브라우저)에 어떻게 전달할까. 콜백은 백엔드로 왔는데 정작 화면은 프론트다. 그래서 **성공 시 프론트 주소로 리다이렉트하면서 토큰을 URL에 실어 보냈다.**

```
https://내프론트주소/#token=<JWT>
```

프론트는 주소의 `#token`을 읽어 저장하고 바로 지운다(주소창에 토큰이 남지 않게). 그러면 자동 로그인된 상태로 채팅 화면이 뜬다.

## 확인

로컬에서 "Google로 로그인"을 눌러봤다. 구글 로그인 화면 → 동의 → 잠깐 우리 서버를 거쳐 → 채팅 화면으로 자동 로그인. 처음 로그인하는 계정은 DB에 새로 만들어졌고, 두 번째부터는 같은 계정으로 붙었다.

## 마무리

OAuth로 소셜 로그인을 붙이며 잡은 감 두 가지.

첫째, **OAuth는 "인증을 구글에 위임하는 것"이다.** 우리는 비밀번호를 안 받고, "이 사람 맞다"는 증표만 받아서 우리 서비스의 세션(여기서는 JWT)을 만든다.

둘째, **소셜 로그인이 곧 우리 로그인은 아니다.** 구글이 신원을 확인해주면, 그걸 받아 우리 서비스의 사용자로 만들고 우리 토큰을 발급하는 마지막 한 단계는 우리 몫이다.

이걸 무상태(JWT) 서버에 붙이는 과정에는 세션이 없어서 생긴 함정이 하나 있었는데, 그건 다음 글에서 따로 정리해 볼 계획이다.
